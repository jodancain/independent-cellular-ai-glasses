# 独立蜂窝智能眼镜开发需求

**v0.1 公开讨论稿 · 2026-11-02**

本文件用于技术方案评审和询价。除明确标为硬性要求的产品边界外，建议配置和测试目标均需通过方案评估及整机实测，由双方冻结。本文不构成性能承诺、采购订单或交期承诺。

## 1 必须满足的产品边界

### 独立蜂窝联网

眼镜脱离手机及手机热点后，仍须通过机内 SIM 或 eSIM 蜂窝网络完成账户登录、工单获取、数据上传和远程协作。蓝牙、Wi-Fi 可以补充使用，不能替代蜂窝独立工作。

### ARM 应用平台与自主软件

采用 ARM 应用主处理器，提供够用的 RAM 和存储，同时优先控制整机功耗。项目方自行开发业务 App、自有账号、后台和 AI 服务，核心功能不得以第三方消费级品牌账号或云服务持续可用为前提。

### 可持续开发和维护

供应商须提供可落地的 BSP、设备接口、系统权限、签名和升级方案。仅交付 APK、封闭演示 SDK 或不可维护的样机，不满足项目目标。第三方授权限制须在立项前明示，不能以违反许可换取交付。

## 2 场景与优先级

| 优先级 | 主要场景 | 所需能力 |
| --- | --- | --- |
| B端优先 | 门店环检、维修指引、零件识别、质检留档 | 摄像与拾音、文字或图示提示、照片视频上传、工单关联 |
| B端优先 | 远程专家、语音派单 | 双向音视频、现场指引、语音交互、弱网恢复 |
| C端预留 | 车况提醒、授权车控、AR 导航 | 获授权的车辆及地图接口；单独定义使用安全边界 |

车控须基于车辆侧授权、身份校验、权限和审计，不承诺硬件天然支持任意车型控制。涉及行车的显示、交互和操作需要单独风险评估，不承诺驾驶中所有功能可用。识别、维修指引和质检结论应保留人工确认及证据链。

显示尚未定型，供应商须分别提交：

- **A档基础 HUD**：文字、箭头及必要的图示提示。
- **B档空间 AR**：说明定位、跟踪、传感器、算法和光学方案及其额外代价。

现阶段不将 6DoF 写成两档共用的硬性要求。

## 3 架构与硬件选项

优先对比 W527 与 W5 系列加蜂窝两条路线，并补充一条供应商已有量产经验的替代方案。详见[芯片候选](chips.md)。比较须使用相同业务负载，覆盖整机功耗、热、性能、重量和成本，不仅比较峰值参数。

### 计算与操作系统

Linux 轻量系统和 Android 均可提案。2GB RAM 加 32GB 存储可作为原型起点；Android 可询价 4GB RAM 加 32–64GB 存储。**这些只是建议候选，不是已确认定值，不代表所有候选芯片都支持。**

供应商须用并发任务剖析给出内存余量、存储寿命、启动耗时和后台策略。Linux 提案须明确业务 App 及设备接口的移植范围、费用和验证责任，不假定与已有 Android 软件直接兼容。

本地重点承担采集、编解码、交互、缓存和必要的轻量推理。复杂识别或大模型可由自有云承载。方案应说明断网可用功能、恢复上传、云端延迟和流量代价，不默认所有 AI 均在眼镜本地完成。

### 模块回复要求

| 模块 | 本方方向 | 供应商须明确 |
| --- | --- | --- |
| 蜂窝与 SIM | 机内独立蜂窝；SIM 与 eSIM 可分选项 | AP、modem、射频前端、天线、卡槽或 eUICC 的完整组合；制式频段、运营商及开通条件 |
| 显示两档 | HUD 与空间 AR 分别提案 | 光学路线、单目或双目、亮度与可读性、视场及屈光适配；空间 AR 另报跟踪定位方案 |
| 摄像与音频 | 质检与远程协作优先 | 传感器、镜头、对焦和防抖选项；麦克风、扬声器、降噪与回声消除；开放接口 |
| 交互与传感 | 语音为主，保留物理交互 | 按键或触控、摄录状态提示、IMU 与定位选项；误触控制 |
| 电源与结构 | 按任务平衡佩戴、重量和续航 | 电池及供电、充电、结构散热、防护、镜腿与鼻托；可维修性及各选项代价 |

### 蜂窝方案必要澄清

eSIM 不是 modem。支持 eUICC 仍需核实模组、运营商接入、认证和中国使用场景是否真正可用；“预留 eSIM”不能写成已经支持。

4G 可作为优先验证路线，不预设必须 5G。供应商应提交头部佩戴条件下的天线布局、RF、SAR、弱信号发射功耗、共存干扰和适用认证验证计划。适用标准和测试范围由供应商识别并解释依据，不在需求阶段虚列未经核实的认证清单。

## 4 软件自主权与交付

### 源码与接口

交付 BSP、可维护的驱动和 HAL、系统服务、设备 API 文档、示例工程、工具链与可复现构建材料。覆盖实际使用的摄像、音频、显示、传感器、蜂窝、电源、按键和存储接口。

列明代码归属、修改与再分发条件、第三方许可证和二进制依赖。无法交付源码的组件，须列出版本、更新与安全修复责任、供应中断后的替代路径，并证明系统仍可构建和升级；无法维护的限制须作为明确偏差回复。

接口契约应明确参数、数据格式、线程模型、错误码、权限、状态机和资源生命周期，尤其是音视频启动、停止、取消、断连重连、多客户端争用和异常退出后的释放语义。可调用 SDK 不等于目标整机已经验证。

### 权限与签名

以下 privileged 权限、白名单及平台签名要求针对 Android。Linux 应提供等效的权限隔离、服务授权和可信升级机制。

| 项目 | 必须提供的路径 |
| --- | --- |
| 系统集成 | 自有应用可按约定预装；所需权限、白名单及系统服务绑定在生产系统中合法配置 |
| 签名与更新 | 平台签名服务或受控集成流程，以及自有应用独立签名和更新路径；不依赖改包重签获得系统权限 |
| 密钥与凭据 | 生产私钥可由供应商保管，但签名服务、交接及退出机制必须可操作；业务凭据不得硬编码，支持配置与轮换 |
| 研发与量产 | 研发样机具有约定的调试与解锁能力；生产 Secure Boot、锁定策略和安全维护另行定义，不以永久关闭安全功能作为方案 |

### OTA 与维护

支持私有化或项目方控制的 OTA 发布流程，明确镜像签名、版本、灰度、失败回退与防降级策略的边界。提供断电、断网或升级损坏后的救砖路径，以及日志、崩溃信息、诊断和工厂恢复工具。

明确供应商停止云服务后设备继续工作的条件。系统补丁、平台升级、缺陷修复、停产替代、维护期、响应方式、构建材料交接及关键件 EOL 通知均须书面报价和约定。

## 5 验证方法与待冻结指标

重量、电池容量、温升、续航、防护等级、摄像分辨率、延迟和预算尚未确认。供应商先提交选项、测量方法与工程样机数据，再由双方冻结门槛。开发板、手机和模拟器结果不能替代真眼镜验收。

| 测试项目 | 方法与证据 | 状态 |
| --- | --- | --- |
| 独立蜂窝闭环 | 关闭手机及热点，验证启动登录、工单、采集上传和远程会话；记录失败恢复 | 硬性功能；覆盖条件待定 |
| 持续音视频 | 1080p30 为建议目标；拾音、显示与蜂窝上行同时运行，报告实际码率、帧率、丢帧、端到端时延及音画同步 | 目标、持续时长待确认 |
| 功耗温升续航 | 同一整机分别测待机、语音、间歇拍摄、持续视频；强弱信号下记录整机功耗、电池、表面温度、降频和关机行为 | 环境及门槛待冻结 |
| 资源与长稳 | CPU、RAM/PSS、线程、文件句柄、存储、异常和重启；覆盖长会话、反复启停及断网恢复 | 时长、循环数与趋势门槛待定 |
| 显示与佩戴 | 室内外可读性、文字箭头、延迟、稳固性和视力适配；空间 AR 额外验证跟踪和漂移 | 两档分别定义 |
| 射频与可靠性 | 头部佩戴、遮挡、移动及弱网；天线共存、RF/SAR、适用认证及跌落、汗液、防护等验证 | 适用项由供应商识别 |
| 权限与升级 | 生产镜像验证权限、升级中断、回退、救砖和凭据轮换 | 需可演示 |
| 隐私与交接 | 摄录提示、访问控制、传输存储保护、保留删除及设备转交清理 | 具体流程待冻结 |

持续蜂窝视频、极低重量、低温和长续航需要共同权衡。不得将不同测试条件下的最好数字拼成整机承诺。

## 6 分阶段开发与商务边界

| 阶段 | 主要成果 |
| --- | --- |
| EVT 工程验证 | 架构、BOM、可调试样机、BSP 和接口初版；独立蜂窝、摄像音频、显示闭环及初步热功耗数据 |
| DVT 设计验证 | 目标结构、生产权限签名路径、关键可靠性和适用认证验证；冻结规格下的长稳、续航、RF 与 OTA |
| PVT 生产验证 | 试产良率、一致性、烧录校准、治具和出厂测试、追溯返修、完整交付及量产放行记录 |

周期、样机数量、各阶段投入和放行条件由供应商提案。报价需分列 BOM、NRE、MOQ、样机、模具、认证、授权、软件与维护费用，并说明关键件来源、替代性、知识产权与模具归属、售后和退出交接。

公开仓库只接收可公开技术信息。具体价格、商业条款、保密 BOM 和采购信息另行交流。请使用[供应商回复模板](supplier-response.md)提交技术方案。
