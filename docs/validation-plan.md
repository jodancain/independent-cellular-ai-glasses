# 现成硬件验证计划

**v0.1 · 2026-11-03 · 对应 [串流终端方向](streaming-direction.md) v0.7**

本计划用**现成设备**（开发板、商用眼镜、PC、开源软件）先验证方案里最关键的假设，再决定自研芯片与结构选型。它不需要自研硬件，也不替代整机验收。

> **证据边界**：本页的“通过标准”全部来自方案中的【设计目标】，不是已验证结论；方案里没有给出数值的，写“待定，首轮测基线后确定”。开发板、商用眼镜的测试结果只能说明趋势，**不能直接当作目标整机数据**。设备型号写“候选，待核实”的，以实际可采购型号为准；本页不含价格和采购承诺。

## 0.1 公共要求

- **共用仪器**：直流功耗分析仪（第 3、4 组）、高速相机或光电传感器 + 毫秒计时页（第 1、2、5 组）、带 NVIDIA 显卡的 Windows PC（第 1、2、5 组）。
- **统一记录**：每轮测试记录设备型号、固件 / 软件版本、环境温度、网络条件；版本或设置改变就另起一轮。延迟类指标至少 30 个样本，报告 p50 / p95。
- **数据与隐私**：原始数据（视频、录音、日志）不放进本公开仓库；仓库只放脱敏后的汇总表。不记录真实设备序列号、SIM 卡号、账号和受试者个人信息。
- **证据标注**：结果写回方案时，标注【实测】及测试条件；未测的仍保留【设计目标】。

## 第 1 组：串流延迟、画质与软件兼容

### 1.1 目的与对应方案章节

本组对应方案第 9 节“建议的第一步验证”第 1 项：用现成 USB-C DP Alt Mode 显示眼镜 + PC 虚拟显示驱动 + 开源串流软件，测延迟、画质与兼容清单通过率。目的不是证明自研整机已经达标，而是取得三类链路的可复现基线，判断哪些指标已有现成方案可以接近、哪些必须留到自研阶段解决。

三个子问题：

- **A1 有线原始画面**：眼镜作为 PC 的 DP 显示器，不经过视频编码；测显示链路延迟、刷新/跳帧、可读字号与 30 分钟稳定性。
- **A2 有线编码**：方案目标是主机编码后经 USB 3.x 数据通道送到眼镜；现成 DP 眼镜没有公开的“编码流直接进显示管线”入口，因此按任务要求用 USB 网络 + Moonlight 近似，并明确标注近似边界。
- **B Wi-Fi 串流**：主机经 Wi-Fi 把编码流送到解码端，再由解码端以 DP 驱动眼镜；测网络与编解码叠加后的延迟、抖动、画质和稳定性。

对应章节：

| 方案章节 | 本组怎么用 |
| --- | --- |
| 第 3.3 节 连接方式 | 定义 A1 / A2 / B 的链路、体验定位与主要前提；A2 的现成方案缺口在本组单独说明 |
| 第 3.5 节 延迟预算 | 引用逐环节设计目标；按 p50 / p95、每组 ≥30 样本、30 分钟连续运行的方法测量 |
| 第 4.1 节 串流纪律 | 记录“最新帧优先、丢帧不排队、不以已发送代替已显示”等行为是否可观察 |
| 第 4.2 节 兼容分层 | 以 L0 系统级虚拟显示器为主路，按软件类别清单测通过率；DRM / 反作弊 / 安全窗口按已知边界记录 |
| 第 3.6 节 眼镜端能力 | 引用 1080p 级每眼起步、90–120 Hz 优先等显示目标，作为选型参照，不作为现成设备的硬性判据 |
| 第 9 节 第一步验证 | 本组即第 1 项；结论服务于完全版样机的芯片与结构选型 |

【项目判断】本组用现成设备时，能测到的是“现成链路的上限/基线”，不是自研眼镜的整机指标。尤其是 A1 的现成眼镜可能没有方案所需的本地重投影，A2 也没有完全等价的现成入口；报告必须把“实测”“近似”“不适用”分开写。

【公开资料】[S20](sources.md#s20) 报道该系列以 USB-C DP 输入并在眼镜端做稳定/畸变校正，宣称约 3 ms；[S37](sources.md#s37) 为公开评测。两者均未经本项目复现，不能当作本组实测结果，也不能替代第 3.5 节的逐环节测量。

### 1.3 测试环境与前置条件

**场地与光学条件**

- 使用暗室或可变光实验室；环境温度控制在 23–27°C，记录实际值；避免阳光直射、频闪光源和强反光。
- 延迟测试把眼镜固定在头模或刚性支架上，减少头动和佩戴位置变化；可读性测试由受试者实际佩戴。
- 固定亮度、对比度、色温，关闭自动亮度和自动色温；记录眼镜的瞳距（IPD）、鼻托位置和眼距。
- 每组测试前清洁镜片和显示面；避免指纹、灰尘影响画质与字号判读。

**链路与网络**

- **A1：** 主机用 USB-C DP Alt Mode 直连眼镜，或 DP 输出经认证的 USB-C 适配器连接；使用认证 USB-C 线，长度 ≤1 m，减少线缆差异。若眼镜无内置电池，按厂商要求供电。
- **A2：** 【项目判断】现成 DP 眼镜没有公开的“主机 USB 3.x 编码流直接进显示管线”入口。本组采用近似路径：主机 PC ↔ USB 3.x 网络（RNDIS/CDC-ECM）↔ 解码端主机 ↔ USB-C DP ↔ 眼镜；Moonlight 走 USB 网络。该路径比方案 A2 多了一次“解码端→眼镜”的 DP 输出，**结论只作为 A2 的近似上界，不外推为 A2 已验证**。
- **B：** 主机用有线接入 Wi-Fi 路由器；解码端与眼镜在同一房间，视距 3 m 左右，记录实际距离；路由器固定信道和频宽，测试期间关闭其他大流量设备。记录实际协商的 Wi-Fi 标准（Wi-Fi 6 / 6E / 7），不默认写成 Wi-Fi 7。
- 记录每次测试的链路：接口、线缆、分辨率、刷新率、编码格式、码率、色度抽样、关键帧间隔、是否切片编码、是否帧内刷新。

**软件与配置**

- 固定操作系统版本、GPU 驱动、虚拟显示驱动版本、Sunshine / Moonlight 版本与配置；每次改配置都重新编号，不把不同配置的数据混在一张汇总表里。
- Windows 主机设为高性能电源模式，关闭睡眠、硬盘休眠和自动更新；解码端同样关闭节能。
- 虚拟显示器的分辨率/刷新率优先匹配眼镜原生规格；若只能低于原生，记录差异。
- A1 不需要虚拟显示驱动；A2/B 用 Virtual-Display-Driver 作为 L0 主路，Linux Breezy Desktop 仅作可选对照，不纳入主通过率。
- 记录是否启用 HDR、是否使用 10-bit、是否开启可变刷新率；首轮建议统一 SDR、固定刷新率，减少变量。

**测量链校准**

- 用已知延迟的 LED 回路或高速相机帧计数校准“输入事件→显示变化”的测量链；记录相机帧率、曝光时间、光电传感器上升时间和示波器采样率。
- 光电法测的是显示面亮度边沿；高速相机法测的是“画面出现对应帧”。两种方法分别记录，不混算。
- 每次测试前后各做一次校准；校准漂移超过预期时，整组重测。

**受试者与安全**

- 受试者使用匿名编号；测试前说明目的、流程、可随时停止；不记录姓名、联系方式、人脸视频等个人信息。
- 避免长时间高亮画面；受试者出现眼干、头痛、眩晕时立即停止。
- 高速相机、三脚架和线缆布置在通道之外，避免绊倒；激光类设备不使用。

### 1.4 测试步骤

1. **登记与编号。** 给每台设备分配实验室别名（如 G1-PC1、G1-GLASS1），记录型号、固件、驱动、软件版本、线缆规格；不记录真实序列号。
2. **校准测量链。** 完成相机/光电/示波器校准，记录校准方法和不确定度；用一次已知延迟的回路验证测量链。
3. **建立 A1 链路。** 主机直连眼镜，设置原生分辨率/刷新率、固定亮度、SDR；确认系统识别为扩展显示器，画面无缩放；记录 DP 链路是否启用显示流压缩（DSC；若启用，注明它是链路压缩，不是 H.264/HEVC 视频编码）。截取系统显示设置和眼镜实际画面作为记录。
4. **A1 内容延迟。** 用“主机画面切换/输入事件→眼镜显示变化”的光电法或高速相机法，每条件至少 30 个有效样本；记录 p50、p95、最大值和全部原始样本。输入事件包括窗口切换、光标移动、视频帧切换，分别记录。
5. **A1 运动到光子（如适用）。** 若眼镜具备端侧稳定/重投影，把眼镜固定在可编程转台或头模上，给一个角运动阶跃，测“运动触发/IMU 触发→显示画面变化”。若眼镜没有重投影，记“不适用”，不得用内容延迟冒充运动到光子；完整 6DoF 追踪与锚定见第 2 组。
6. **A1 帧率、跳帧与画质。** 连续运行 10 分钟，记录平均/最低帧率、应显示帧数、丢弃或迟到帧数；用测试图案检查原生分辨率、色带、块效应、文字边缘和运动模糊。A1 的定位是“无压缩画质”，但仍需记录眼镜端缩放/校正带来的变化。
7. **A1 可读字号。** 在固定等效距离（首轮 2 m，记录实际）显示中英文和数字字号图卡；分别在 100%、125%、150% 缩放下，由至少 3 名受试者判读；5 次中 4 次正确记为“可读”，记录最小字号和对应角分。
8. **A1 30 分钟稳定性。** 用代表性负载（办公窗口 + 视频播放 + 滚动/拖拽）连续运行 30 分钟；在 0–5 分钟和 25–30 分钟分别测 p95 延迟（每个窗口至少 30 个有效延迟样本）、帧率和温度；每 1 分钟记录前框、左右镜腿、显示面温度和环境温度；记录是否出现降频、花屏、断连。
9. **A2 近似链路。** 按本组 1.3 节的 USB 网络路径搭建；主机用 Virtual-Display-Driver 创建与眼镜原生分辨率匹配的虚拟显示器，Sunshine 捕获该显示器；确认 Moonlight 走 USB 网络而不是 Wi-Fi；重复第 4–8 步的延迟、帧率、字号和 30 分钟稳定性测试。报告中写明“A2 近似，不是方案 A2 的等价实现”。
10. **B Wi-Fi 链路。** 主机有线接路由器，主机用同一虚拟显示器配置并由 Sunshine 捕获；解码端 Wi-Fi 接入；记录频段、信道、频宽、RSSI、协商速率；重复第 4–8 步。若路由器/解码端不支持 Wi-Fi 7，按实际标准记录，并把“Wi-Fi 7”结论留空。
11. **兼容清单。** 在 A1 和 B 上逐项运行本组 1.5 节清单；每项至少完成一次完整操作，失败项复测一次；按“通过 / 部分通过 / 失败 / 预期失败”记录，预期失败项注明方案 4.2 的边界。DRM、反作弊、安全窗口不尝试绕过。
12. **汇总与复测。** 检查样本量、校准记录和异常样本；对 p95 异常、温度异常或兼容结果不一致的条件，按同一配置复测一次并保留两次数据。

### 1.5 测量指标与方法

**1.5.1 内容延迟与运动到光子**

- **内容延迟**：从主机输入事件（窗口切换、光标移动、视频帧切换）或画面切换命令，到眼镜显示面出现对应变化的时间。A1 用光电法或高速相机法；A2/B 在眼镜显示面测量，包含采集、编码、传输、解码、显示。
- **运动到光子**：从台架角运动触发或 IMU 触发，到显示画面出现对应变化的时间。只对具备端侧稳定/重投影的现成眼镜测量；没有重投影的型号记“不适用”，并说明原因。
- 每个条件至少 30 个有效样本；记录 p50、p95、最大值、最小值；p95 用 nearest-rank。无效样本（遮挡、自动亮度变化、丢帧、对焦失败）单独保留并注明原因，不直接删除。
- 同时记录测量链不确定度；若相机帧间隔大于目标延迟，必须用光电法或更高帧率设备补充，不能只靠低帧率相机下结论。

**1.5.2 帧率与跳帧**

- 帧率用主机端呈现统计工具、客户端统计叠加层和高速相机抽检三种方式交叉核对；记录平均 fps、最低 fps、测试时长。
- 跳帧率定义为“丢弃或迟到超过 1 个刷新周期的帧数 ÷ 应显示帧数”；同时记录“迟到但未丢弃”的帧，避免把网络抖动误判为跳帧。
- 记录是否出现“排队而不是丢帧”：若延迟随时间单调上升、恢复后出现追赶，按方案 4.1 的串流纪律单独记录。

**1.5.3 画质**

- 记录原生分辨率、实际输出分辨率、刷新率、色度抽样、色深、是否 HDR；用测试图案检查色带、块效应、振铃、文字边缘和运动模糊。
- A1 的定位是“无压缩画质”，检查重点是眼镜端缩放/畸变校正、面板均匀性和文字清晰度；A2/B 额外记录编码伪影和码率变化。
- 画质目前没有方案数值阈值，首轮以“可复现的描述 + 对比截图/照片”记录，阈值待定，首轮测基线后确定。

**1.5.4 最小可读字号**

- 固定等效距离、字体、字重、对比度和背景；中英文、数字分别测试；记录 100%/125%/150% 缩放下的最小可读字号。
- 每名受试者每个条件读 5 次，4 次正确记为可读；记录错误类型（看错、看不清、串行）。
- 同时记录受试者的矫正视力状态（只写“已矫正/未矫正”，不写具体病历）。

**1.5.5 30 分钟稳定性**

- 统一负载和亮度，连续 30 分钟；在 0–5 分钟和 25–30 分钟两个窗口分别计算 p95 延迟、平均帧率、跳帧率。
- 温度每 1 分钟记录一次：前框、左镜腿、右镜腿、显示面、环境；记录是否出现降频、亮度下降、断连、花屏。
- 30 分钟 p95 相对 0–5 分钟基线的劣化幅度、温度上限均无方案数值，按“待定，首轮测基线后确定”处理。

**1.5.6 兼容清单与通过率**

按方案 4.2 的 L0 主路，覆盖以下类别；具体应用只写类别和场景，不写登录信息：

| 类别 | 场景 |
| --- | --- |
| 办公 | 文字处理、表格、演示、PDF、浏览器、邮件/日历、多窗口 |
| 开发 | 编辑器/IDE、终端、浏览器开发者工具、编译/测试、多显示器 |
| 影音 | 本地视频播放器、浏览器视频、字幕、DRM 流媒体（预期失败） |
| 游戏 | 窗口/无边框游戏、游戏启动器、反作弊游戏（预期失败） |
| 手机应用 | Android 投屏/桌面模式/模拟器；另一手机生态仅记录是否可用 |
| 安全窗口 | 登录/提权/口令输入框、银行类安全界面、DRM/HDCP 安全路径（预期失败） |

- 结果定义：**通过** = 主要功能可用且内容可读；**部分通过** = 可用但有明确限制（如必须缩放、部分弹窗不可见）；**失败** = 主要功能不可用；**预期失败** = 方案 4.2 已列明的边界（DRM、反作弊、安全窗口等）。
- 通过率分别计算“严格通过率 = 通过 ÷（总项 − 预期失败）”和“含部分通过率 =（通过 + 部分通过）÷（总项 − 预期失败）”；两个数都记录，不用一个数掩盖差异。
- 失败项复测一次；仍失败则记录系统版本、应用版本、窗口模式和复现步骤，不尝试绕过 DRM、反作弊或安全机制。

**1.5.7 记录与隐私**

- 原始 CSV、视频、照片保存在受控目录，不放入公开仓库；公开仓库只放模板和汇总。
- 不记录真实序列号、登录信息、个人信息；设备用实验室别名，受试者用匿名编号。

## 第 2 组：6DoF 虚拟屏锚定 + 手势交互

### 2.1 目的与对应方案章节

本组对应方案第 9 节“建议的第一步验证”第 2 项：用现成 6DoF 一体机或光学透视 AR 开发套件，验证“虚拟屏锚定在真实桌面 + 手势操作”的交互是否满足需求。重点是 6DoF 真实画面交互，不追求完整 VR 游戏；不要求现成设备具备自研眼镜的全部能力。

要回答的问题：

- 虚拟屏能否稳定锚定在真实桌面上方，而不是固定在眼前。
- 佩戴者走动、转头后，虚拟屏相对桌面的漂移量有多大；是否影响阅读和点选。
- 手势点选、拖拽、缩放的成功率、完成时间和误触率如何；目标大小、距离、手部姿态如何影响结果。
- 连续使用 30 分钟的主观舒适与疲劳如何；是否有眼干、颈酸、眩晕。
- 与 PC 串流结合时，虚拟显示器能否作为锚定屏，延迟、帧率、漂移和可读性是否仍可接受。

对应章节：

| 方案章节 | 本组怎么用 |
| --- | --- |
| 第 3.1 节 VR 级能力、AR 效果 | 6DoF 追踪、空间锚定、手势交互、平面/物体识别是基础能力；不追求完整 VR 游戏 |
| 第 3.2 节 算力分工 | 追踪/手势/重投影在本地，内容渲染在主机或云；本组用现成一体机近似本地追踪 + 主机渲染 |
| 第 3.3 节 连接方式 | B Wi-Fi 串流作为“PC 串流 + 锚定屏”的链路 |
| 第 3.5 节 延迟预算 | B 链路逐环节设计目标；运动到光子与网络延迟解耦 |
| 第 4.2 节 兼容分层 | L0 虚拟显示器在眼镜里作为虚拟屏幕锚定在真实空间（如桌面上方），可多屏摆放 |
| 第 7.3 节 佩戴无感 | 2 小时连续佩戴的主观舒适目标；本组 30 分钟只作早期基线，不把 2 小时目标当 30 分钟结论 |
| 第 9 节 第一步验证 | 本组即第 2 项；结论服务于交互方案与 6DoF 硬件选型 |

【项目判断】现成一体机通常是视频透视（VST），而方案要求光学透视（OST）。本组应尽量同时准备一台 OST 开发套件做对照；若只能拿到 VST 设备，结论要写明“VST 近似”，不能直接代表 OST 的亮度、视场和真实画面体验。

### 2.3 测试环境与前置条件

**场地与桌面**

- 使用至少 3 m × 3 m 的空旷区域，地面防滑，移除桌椅、线缆等障碍；设置安全边界，站立/走动测试必须有陪同人员在旁。
- 桌面高度首轮统一为 0.75 m（记录实际值）；桌面布置 4–6 个标记点，建立桌面坐标系；标记点位置用卷尺/激光测距记录。
- 虚拟屏初始位姿首轮固定为：屏幕中心距桌面约 0.45 m、距坐姿眼位约 0.8 m，屏幕朝向佩戴者；该参数是测试条件，不是方案指标，后续可按交互方案调整。
- 环境光可调并记录实际照度；避免阳光直射、强反光和纯白无纹理墙面；必要时增加墙面纹理或标记点，减少追踪丢失。
- 房间内避免大面积镜面、动态人群和强频闪光源；测试期间保持布局稳定，不移动桌面和标记点。

**设备与校准**

- 记录头显/开发套件的固件、系统版本、OpenXR 运行时、手部追踪版本、刷新率、亮度、瞳距（IPD）、护目镜间距。
- 每名受试者先调整 IPD 和佩戴位置，完成手部追踪校准；给 2 分钟练习，确认能完成点选、拖拽、缩放各 3 次后再开始计时。
- 清除旧房间地图/锚点，按统一流程重新建图；记录建图方式、锚点类型（平面/标记/空间锚点）和是否持久化。
- 外部参考系统先校准到桌面坐标系，记录参考精度；若没有动作捕捉，用标记点 + 摄影测量，报告中注明不确定度，不能把“看起来没动”当成零漂移。

**串流与网络**

- PC 有线接路由器，头显 Wi-Fi 接入；记录频段、信道、RSSI、协商速率；测试期间关闭其他大流量设备。
- 先测本地锚定与手势，再测 PC 串流 + 锚定屏；避免把网络延迟混入追踪/锚定结论。
- 串流分辨率/刷新率/码率固定并记录；若设备支持异步空间扭曲/重投影/插帧，记录是否开启，因为会影响运动到光子和漂移的主观感受。
- PC 串流优先用 Sunshine/Moonlight 的平面串流（虚拟显示器作为锚定屏）；ALVR/WiVRn 只作 OpenXR 对照，不混入同一组通过率。

**受试者与安全**

- 受试者匿名编号；测试前说明流程、可随时停止；不记录姓名、联系方式、人脸视频。
- 站立/走动前确认安全边界；佩戴者视线被遮挡时由陪同人员引导；出现眩晕、恶心、头痛、眼干时立即停止。
- 不在有台阶、玻璃、尖锐物或人员的区域走动；不进行快速转身、跑跳等高风险动作。

### 2.4 测试步骤

1. **登记与编号。** 给设备、测试场景、受试者分配别名；记录固件、运行时、刷新率、手部追踪版本、锚定方式。
2. **布置桌面与参考。** 按本组 2.3 节布置桌面、标记点和安全边界；校准外部参考到桌面坐标系；记录桌面高度、屏幕初始位姿和参考精度。
3. **佩戴与校准。** 调整 IPD/佩戴位置，完成手部追踪校准；练习点选、拖拽、缩放各 3 次；记录是否需要重复校准。
4. **建立锚定屏。** 在桌面上方放置虚拟屏，记录初始位姿（x, y, z, yaw, pitch, roll）；截取画面和外部参考读数；确认屏幕不跟随头部。
5. **静态漂移。** 坐姿、头部自然小幅活动、无手势操作，连续 10 分钟；每 10 秒采样一次虚拟屏位姿，记录最大/平均漂移；同时记录追踪丢失次数。
6. **转头漂移。** 坐姿完成 yaw ±60°、pitch ±30° 的转头，各 10 个来回；回到初始视线后测量虚拟屏相对桌面的位姿；有条件时在转头过程中连续采样位姿，记录最大动态漂移；同时记录追踪丢失、画面跳动和重锚。
7. **走动漂移。** 站立，向前走约 3 m、转身 180°、返回座位；重复 3 次；每次返回后测量虚拟屏位姿；有条件时在走动过程中连续采样，记录最大动态漂移；同时记录追踪丢失、重锚和是否需要重新定位。
8. **手势点选。** 在屏幕中心和边缘布置目标，目标角大小/距离分级；每种条件 30 次点选；记录成功/失败、完成时间、错误目标、是否需要用另一只手辅助。
9. **手势拖拽。** 拖动窗口/滑块/图标，每种条件 30 次；记录起点命中、拖动过程是否脱手、落点误差、完成时间。
10. **手势缩放。** 按设备支持的缩放手势（单/双手）缩放图片/窗口，每种条件 30 次；记录缩放方向、比例误差、是否误触其他控件、完成时间。
11. **误触测试。** 手自然放在目标附近、从目标前经过、做非交互手势，各 30 次；记录是否触发意外点选/拖拽/缩放；区分“系统误识别”和“受试者误操作”。
12. **30 分钟连续使用。** 交替进行阅读、窗口拖拽、图片缩放和视频观看；每 5 分钟记录舒适度、疲劳、眼干、颈酸、眩晕；测试前后各填一次 SSQ；记录温度、追踪丢失和漂移。
13. **PC 串流 + 锚定屏。** 用 PC 虚拟显示器输出桌面，优先经 Sunshine/Moonlight 平面串流到头显；把串流窗口作为锚定屏放在桌面上方；测延迟、帧率、跳帧、漂移、最小可读字号和 15 分钟稳定性；记录串流参数与网络指标。
14. **会话恢复。** 依次执行睡眠/唤醒、应用重启、主机重连、走动后返回；记录锚点是否保持、重锚时间、重锚后漂移；若必须重新建图，记录原因。
15. **汇总与复测。** 对漂移异常、手势成功率异常、舒适度骤降的条件，按同一配置复测；保留全部原始记录和问卷。

### 2.5 测量指标与方法

**2.5.1 虚拟屏锚定漂移**

- **定义**：虚拟屏在桌面坐标系中的实测位姿与初始参考位姿之差；位置用 mm，姿态用度（yaw/pitch/roll）。
- **采样点**：屏幕中心 + 四个角；至少记录中心和一角，条件允许时记录四角，观察是否有旋转/缩放漂移。
- **测量方法**：外部光学参考/摄影测量读取头显与桌面标记的相对位姿，再换算虚拟屏位姿；若只能通过系统 API 读取锚点位姿，需注明“系统自报，非外部真值”。
- **阶段**：初始、静态 10 分钟、转头后、走动后、30 分钟结束、串流 15 分钟结束。
- **统计**：每个阶段记录最大漂移、平均漂移、漂移方向；样本数、采样间隔和参考不确定度一并记录。

**2.5.2 手势交互**

- **成功率** = 成功完成次数 ÷ 总试次；成功定义需在测试前固定（如“命中正确目标并完成预期动作”）。
- **误触率** = 非预期触发次数 ÷ 误触测试机会数；同时记录误触类型（误点、误拖、误缩放、误关闭）。
- **完成时间**：从目标出现/手势开始到动作完成的时间；记录中位数和 p95。
- **目标条件**：中心/边缘、近/远、不同角大小；左右手分别记录；记录目标是否被手部遮挡。
- **失败分类**：未命中、命中错误目标、拖拽脱手、缩放方向错误、系统未识别、受试者主动放弃。

**2.5.3 主观舒适与疲劳**

- 每 5 分钟记录 0–10 舒适度（10 最舒适）和 0–10 疲劳（10 最疲劳）；记录眼干、颈酸、眩晕、恶心、头痛的有无与程度。
- 测试前后填 SSQ；记录总分和主要症状；不把 SSQ 当作诊断，只作相对比较。
- 记录受试者是否提前停止、停止原因和时间；提前停止也是结果，不能从数据中删除。
- 30 分钟是早期基线；方案 7.3 的 2 小时连续佩戴目标是后续整机验收，不直接套用到本组。

**2.5.4 PC 串流 + 锚定屏**

- 串流链路按第 1 组 B 的方法测：编码、传输、解码、重投影+显示分段记录；p50/p95；至少 30 个延迟样本。
- 记录分辨率、刷新率、码率、编码格式、RSSI、重传、跳帧率；区分“网络抖动”和“头显解码/渲染瓶颈”。
- 锚定屏可读性：在固定距离下测最小可读字号；记录串流压缩对文字边缘的影响。
- 漂移：串流前后各测一次虚拟屏位姿；记录串流期间是否出现锚点漂移、画面跟随头部、黑边/花屏。
- 温度：记录前框、镜腿和显示面温度；记录是否降频、亮度下降。

**2.5.5 追踪与会话恢复**

- 记录追踪丢失次数、每次丢失时长、恢复方式（自动恢复/重锚/重启应用/重新建图）。
- 记录睡眠/唤醒、应用重启、主机重连、走动返回后的锚点保持情况；重锚时间从操作开始到画面稳定可用。
- 记录是否必须使用手柄/手机辅助；若手势不可用，记录替代输入方式。

**2.5.6 光学透视对照（如使用 OST 套件）**

- 记录亮度、对比度、视场、透视效果、重影/彩虹效应、户外可见性（仅室内测试则注明）。
- 记录虚拟屏在真实桌面上的遮挡关系、文字可读性和长时间观看舒适度；与 VST 设备分开报告，不混算。

## 第 3 组：5G RedCap 联网与睡眠功耗

### 3.1 目的与对应方案章节

本组对应方案第 9 节“建议的第一步验证”第 3 项：用 RedCap 模组开发板、精密电流表/功耗分析仪和运营商 5G SA 卡，实测 eDRX / PSM 休眠、唤醒时间、强弱信号下的持续速率与 RTT，并对照方案第 6.3 节的串流最低网络要求。特别针对 S23 中“RG255C eDRX 不生效、休眠电流偏高”的公开用户反馈设计专项用例；该反馈是【公开资料·用户反馈，未经本项目复现】[S23](sources.md#s23)，是待核实线索，不是已验证结论。

要回答的问题：

- S2 待机场景下，eDRX / PSM 是否真正生效；休眠电流是多少；电流波形是否出现预期休眠窗口。
- 从休眠/寻呼唤醒到“可用”需要多长时间；p50/p95 是多少。
- 强信号和弱信号下，持续下行/上行速率、RTT p95、丢包如何；能否满足方案 6.3 的云串流、视频通话、串流+通话并发三档要求。
- S23 的 eDRX 不生效/休眠电流偏高是否能在本组复现；在哪些配置、频段、SIM、固件下出现。
- 模组/评估板的功耗与发热是否会影响持续速率；需要哪些整机层面的补充验证。

对应章节：

| 方案章节 | 本组怎么用 |
| --- | --- |
| 第 5.1 节 分级功耗状态 | S2 待机：主处理器挂起、协处理器只跑佩戴检测/IMU/唤醒词、蜂窝 eDRX/PSM；本组只测蜂窝子系统，不代表整机 S2 |

### 3.3 测试环境与前置条件

**网络与信号**

- 使用运营商 5G SA 现网或经运营商确认的测试环境；记录频段、PCI、RSRP、SINR、注册状态、PDP/PDU 会话状态；不记录卡号、IMSI、IMEI、真实设备序列号等标识。
- 强弱信号用射频屏蔽箱 + 可编程衰减器实现，优先 conducted（传导）测试，避免空口干扰他人网络。强信号首轮用 0–10 dB 衰减；弱信号逐步增加衰减，直到 RSRP 约 -110 dBm 且仍保持连接，记录实际 RSRP/SINR；若中途掉网，回退一档并记录。以上是测试条件，不是通过阈值。
- 不在没有授权的情况下扫描、接入或干扰他人网络；测试卡、APN、服务器白名单由运营商/项目方按规定提供。
- 记录测试时间、小区负载的主观/可观测情况（如时段、是否拥塞）；同一条件至少重复 3 次，避免单次网络波动被当成设备结论。

**供电与电流测量**

- 按模组规格的标称供电电压供电；使用四线/Kelvin 连接或高边分流，减少线损和 burden voltage。
- 源表量程要覆盖“µA 级休眠—安培级发射脉冲”；记录量程、采样率、分辨率、 burden voltage 和校准日期。
- 优先测“模组 + 必要外围”的板级电流；若测整板，记录板上 LED、电平转换、USB 转串口等额外负载，必要时分别测“只给模组”和“整板”两组。
- 休眠电流不能用 USB 口电流或普通功率计近似；必须用能测 µA 级且能捕捉脉冲的设备。
- 测试前预热 10–15 分钟；记录环境温度、屏蔽箱内温度和板卡温度；避免阳光直射和风扇直吹。

**软件与配置**

- 记录模组型号、固件、AT 版本、评估板版本、天线、SIM/运营商代号、APN 类型（不写具体字符串）、测试服务器别名（不写内部地址与凭据）。
- AT 命令以模组手册为准；本组使用的通用命令包括 `AT+CEREG?`、`AT+CGATT?`、`AT+CSQ`、`AT+CPSMS?`、`AT+CEDRXS?`、`AT+CEDRXRDP`（如支持）；不同厂商/固件可能不同，记录实际命令与返回。
- 固定数据业务状态：注册、PDU 会话激活、无应用数据；关闭 Wi-Fi/蓝牙等无关射频；关闭模组自带的调试输出或高频轮询，避免唤醒。
- 记录 PSM/eDRX 的请求值和网络协商值；若模组不暴露协商值，用电流波形和唤醒行为判断，并在报告中写明“未能直接读取协商值”。

**安全与合规**

- 屏蔽箱接地、防静电；发射时遵守当地无线电管理规定和运营商要求；不长时间在密闭、散热不良的箱体内满功率发射。
- 测试服务器只用于本项目测试；不做端口扫描、压力攻击或影响他人网络的操作。

### 3.4 测试步骤

1. **登记与编号。** 给模组、评估板、SIM、天线、服务器分配别名；记录固件、AT 版本、频段能力、APN 类型、测试时间；不记录卡号/IMEI/序列号。
2. **建立链路。** 连接天线/屏蔽箱/衰减器，插入测试卡，上电注册；用 `AT+CEREG?`、`AT+CGATT?`、`AT+CSQ` 确认注册和信号；建立 PDU 会话；记录频段、RSRP、SINR。
3. **查询能力与当前配置。** 用 `AT+CPSMS?`、`AT+CEDRXS?`、`AT+CEDRXRDP`（如支持）查询 PSM/eDRX 当前配置与动态参数；记录请求值、模组返回值和网络协商值（能读到多少记多少）。
4. **建立对照基线。** 关闭 eDRX 和 PSM，保持注册和 PDU 会话、无应用数据；稳定 10 分钟后，用源表连续记录 ≥10 分钟电流波形；记录平均电流、峰值、唤醒/寻呼脉冲；这是后续节能配置的对照。
5. **PSM 单开。** 按模组支持范围请求 PSM（记录请求的 T3324/T3412 等参数）；确认网络是否授予；保持无应用数据，连续记录至少 10 分钟，且覆盖 ≥3 个 PSM 周期（以较长者为准）；记录休眠窗口、平均/峰值电流、唤醒次数。若网络拒绝，记录拒绝行为，不反复强制。
6. **eDRX 单开。** 按模组支持范围逐档请求 eDRX 周期；确认网络是否授予；每档连续记录至少 10 分钟，且覆盖 ≥3 个 eDRX 周期（以较长者为准）；记录实际周期、休眠窗口、平均/峰值电流、寻呼唤醒次数。不要预设“某个周期一定生效”。
7. **eDRX + PSM 组合。** 同时请求 eDRX 和 PSM，重复第 5–6 步的电流记录；比较单开/组合/关闭三种配置的休眠电流和唤醒行为。
8. **S23 专项：eDRX 不生效/休眠电流偏高。** 按 S23 的公开反馈设计用例：请求 eDRX 后检查网络是否授予、电流波形是否出现预期休眠窗口、休眠电流是否明显高于对照；至少重复 3 次，并分别更换频段、SIM/运营商、固件版本（在可用范围内）复测；记录是否复现、在哪种组合下复现。该反馈未经本项目复现，不能先写成结论。
9. **唤醒到可用。** 在 PSM/eDRX 休眠状态下，优先由服务器发起下行数据（ping/HTTP/iperf）或寻呼触发；AT/控制主机触发只作对照；记录三个时间点：UART/模组可响应、PDU 会话可用、首个应用层请求成功；以“首个应用层请求成功”作为“可用”；每条件 ≥30 次，记录 p50/p95/失败次数。
10. **强信号持续速率。** 在强信号档，用 iperf3 分别测下行 60 秒、上行 60 秒，各 3 次；记录平均速率、最低速率、p50、丢包、频段/RSRP/SINR、温度；再做双向并发 60 秒。
11. **弱信号持续速率。** 增加衰减到弱信号档，重复第 10 步；若掉网，回退一档并记录；弱信号下的结果单独报告，不与强信号混合。
12. **RTT 与丢包。** 对测试服务器做 ping/UDP 探测，至少 300 个样本；记录 p50、p95、最大值、丢包；分别测空闲和持续下行/上行时的 RTT；记录服务器位置/路由（只写可公开的网络位置类别，不写内部地址）。
13. **持续负载与发热。** 以并发下行/上行或持续下行运行 30 分钟，记录速率、RTT、电流、模组/板卡温度；观察是否降速、掉网、重启；记录恢复时间。
14. **对照 6.3 与汇总。** 把强/弱信号结果对照第 6.3 节三档要求；未达标项保留原始数据并记录可能原因（信号、拥塞、服务器、模组、APN、频段）；对异常条件复测一次。

### 3.5 测量指标与方法

**3.5.1 eDRX / PSM 是否真正生效**

- 记录“请求值—网络协商值—实际电流波形”三者；只有电流波形出现与协商周期一致的休眠窗口，才记为“观察到生效”；仅 AT 返回“已设置”不算生效。
- 记录 PSM 的激活时间/周期参数、eDRX 周期、寻呼窗口；若模组不暴露协商值，记录“未能直接读取”，并用波形推断，标注推断性质。
- 记录生效/不生效的判定依据、判定人、原始波形文件编号；不把论坛反馈或厂商宣传当作判定依据。

**3.5.2 休眠电流**

- 稳定窗口至少 10 分钟，且覆盖 ≥3 个节能周期（以较长者为准）；记录平均电流、峰值电流、休眠占空比（休眠窗口时间 ÷ 统计窗口时间）、唤醒/寻呼次数。
- 采样率 ≥1 kSa/s（能捕捉 ms 级脉冲）；记录量程、分辨率、burden voltage、校准日期；µA 级测量要给出不确定度。
- 分别报告“只给模组”“模组 + 必要外围”“整板”三种口径；整机 S2 不能由板级数据直接外推。
- 记录温度对电流的影响；必要时在相同温度起点复测，避免温度漂移被当成配置差异。

**3.5.3 唤醒到可用**

- 定义：从下行数据到达/寻呼唤醒开始，到首个应用层请求成功（如 HTTP 200、iperf 首包）为止；同时记录 UART 可响应、PDU 可用两个中间时间点。
- 每条件 ≥30 次；记录 p50、p95、最大值、失败/超时次数；区分“冷唤醒”（长时间休眠后）和“热唤醒”（刚休眠）。
- 记录唤醒源、寻呼周期、重试次数；若首次失败后重试成功，记录总时间和重试次数。

**3.5.4 持续速率、RTT 与丢包**

- 下行/上行各 60 秒，重复 3 次；记录平均、最低、p50；并发用双向 iperf3 或同时下行/上行。
- RTT 至少 300 个样本，记录 p50/p95/最大值和丢包；区分空闲 RTT 与负载 RTT；RTT 是网络层指标，不等同于串流端到端内容延迟，后者按第 1 组方法另测。
- 同时记录频段、RSRP、SINR、调制/编码（能读到才记）、服务器位置类别、测试时段；不把不同信号条件的数据拼成一个“最好值”。

**3.5.5 对照方案 6.3**

- 按云串流、视频通话/会议、串流+通话并发三档逐项对照；每一档同时看下行、上行、RTT，不用单一速率指标代替。
- 6.3 未区分强/弱信号；强信号先测，弱信号单独报告。弱信号下是否允许降级、降级后是否仍算满足 6.3，方案未明确，标注“待定，首轮测基线后确定；是否允许降级另待方案确认”。
- 未达标时保留原始数据，记录可能原因；不通过修改 6.3 阈值或只报最好一次来“通过”。

**3.5.6 发热与整机边界**

- 记录模组、板卡、屏蔽箱和环境温度；持续负载下是否降速、掉网、重启。
- 记录评估板额外负载（LED、USB 转串口、电平转换等）；整机 S2 还需加协处理器、传感器、电源转换，另立整机测试。

### 4.1 目的与对应方案章节

### 4.3 测试环境与前置条件

- 室温 23–27 °C；开发板去掉调试器供电或单独测量调试器电流后扣除。
- 关闭开发板上与眼镜无关的外设（以太网、LED、USB 转串口等），记录关闭清单，保证各轮一致。
- 固件版本、编译选项、主频固定后再测，任何改动都另起一轮。

### 4.4 测试步骤

1. **待机基线**：只运行实时时钟和显示局部刷新（每分钟更新时间），测 10 分钟平均电流。
2. **看时间**：模拟按键唤醒 → 显示时间 5 s → 熄屏，重复 30 次，测单次能耗和唤醒到显示的时间。
3. **拍照**：按键 → 拍照 → 存储，重复 30 次，测单次能耗、按键到成像时间。
4. **录像**：1080p30（若板子不支持则用其最高规格并记录）H.264 录 10 分钟，测平均功耗、温度、存储写入速度、是否丢帧。
5. **录音**：双麦录音 30 分钟，测平均功耗。
6. **小程序**：分别用 WebAssembly 与 Lua 实现同一个计时器小程序和一个清单小程序，测内存占用、启动时间、运行 10 分钟平均功耗；验证沙箱限制（不能访问网络、内存超限被终止、摄像头需确认）。
7. **一天剖面推算**：按方案第 5.3 节剖面中“手表模式 1 小时”的组合，把第 1–6 步结果加权，算出该时段电量。
8. **模式切换**（如有主处理器开发板可配合）：模拟“联网 → 断网”切换，测进入手表模式的时间；拍照时唤醒主处理器 ISP 与只用协处理器 ISP 两种做法各测一次能耗。

## 第 5 组：视频通话接入（虚拟摄像头）与虚拟形象

### 5.1 目的与对应方案章节

验证“眼镜摄像头和麦克风注册为主机的摄像头和麦克风”（V1 主机通话）能否让主流通话软件不做任何适配就可用，以及虚拟形象能否作为一路视频进入通话。对应方案第 3.7 节（视频通话三种接入方式）和第 3.8 节（虚拟形象）。

### 5.2 设备清单

| 类别 | 建议型号或规格 | 数量 | 备注 |
| --- | --- | --- | --- |
| “眼镜摄像头替身”（有线） | 支持 USB 设备模式的 Linux 小板 + 摄像头模组，配置为 UVC 摄像头 [S30](sources.md#s30)，固定在眼镜架上模拟第一人称视角 | 1 | 模拟方案的有线 UVC 路径 |
| “眼镜摄像头替身”（无线） | 带摄像头的 Android 手机或小板，经 Wi-Fi 推流到 PC，由 PC 端虚拟摄像头接收 | 1 | 模拟无线路径；虚拟摄像头可用 OBS 虚拟摄像头等开源方案（新增来源 N1） |
| 麦克风 | USB 麦克风阵列或带降噪的 USB 音频设备 | 1 | 模拟眼镜麦克风作为主机音频输入 |
| PC（Windows） | 带 NVIDIA 显卡 | 1 | 第 1 组可共用；虚拟形象需 NVIDIA 显卡 |
| Mac / 手机 | 各 1 | — | 覆盖不同主机系统 |
| 通话软件 | 微信（PC）、腾讯会议、Microsoft Teams、Zoom；可选浏览器内 WebRTC 会议 [S31](sources.md#s31) | — | 使用测试账号 |
| 虚拟形象 | Audio2Face-3D SDK [S32](sources.md#s32) + 渲染引擎 + 虚拟摄像头输出 | — | 许可条款先核实 |
| 对端设备 | 一台普通手机或电脑作为通话另一端 | 1 | 主观评价画面与声音 |

### 5.3 测试环境与前置条件

- 通话软件使用专门的测试账号，不用个人或公司账号；对端由测试人员自己操作。
- 网络：同一 Wi-Fi 下测一轮；再用第 3 组 RedCap 链路或手机 5G 热点测一轮弱网。
- 虚拟形象只用测试人员本人形象或卡通模板，画面角标“虚拟形象”。

### 5.4 测试步骤

1. **有线 UVC**：把替身板接 PC，确认系统识别为摄像头；在每个通话软件里选择该摄像头和麦克风，发起 5 分钟视频通话。
2. **无线虚拟摄像头**：替身设备经 Wi-Fi 推流到 PC，PC 端虚拟摄像头输出；重复第 1 步。
3. **屏幕共享**：在通话中共享第 1 组的虚拟显示器画面，确认对端可见。
4. **口到耳与画面延迟**：在替身摄像头前放毫秒计时器，对端录屏比对时间差；口到耳延迟用拍手 + 双端录音比对，各取 ≥ 30 样本。
5. **弱网**：限速到上行 2 Mbps、1 Mbps，记录分辨率、卡顿、断线情况。
6. **虚拟形象**：用通话音频驱动 Audio2Face 生成口型，叠加头部姿态（可用手机 IMU 模拟），渲染结果输出为虚拟摄像头；在每个通话软件里选用，测端到端延迟和对端主观自然度。
7. **长时**：选一个软件连续通话 30 分钟，记录 PC 资源占用和是否中断。

### 5.5 测量指标与方法

| 指标 | 方法 |
| --- | --- |
| 通过率 | 每个软件 × 每种接入方式：能选中设备、能正常通话 5 分钟视为通过 |
| 画面延迟、口到耳延迟 | 计时器 / 拍手比对，p50 / p95 |
| 弱网表现 | 分辨率、卡顿次数、恢复时间 |
| 虚拟形象 | 口型与语音的时间差（录屏逐帧比对）；对端 5 分制主观自然度（≥ 3 人） |

### 5.6 通过标准

| 项目 | 标准 | 依据 |
| --- | --- | --- |
| V1 兼容 | 列出的主流通话软件都能识别虚拟摄像头与麦克风并正常通话；个别软件限制虚拟设备的，记录为已知边界 | 方案第 3.7 节【设计目标，非已验证结论】 |

## 第 6 组：佩戴无感基线（人体工学）

### 6.1 目的与对应方案章节

方案已定“续航优先，重量分配好，让人尽量无感”，整机可能约 95–110 g。本组用现成主流眼镜建立“鼻梁受力”和“主观舒适度”基线，并用配重样架验证“重量后移到耳后”能否在更重的情况下保持无感。对应方案第 7.2、7.3 节。

### 6.2 设备清单

| 类别 | 建议型号或规格 | 数量 | 备注 |
| --- | --- | --- | --- |
| 对标眼镜 | Ray-Ban Meta（Gen 2）、Meta Ray-Ban Display、XREAL One（或 One Pro）[S35](sources.md#s35)[S36](sources.md#s36)[S37](sources.md#s37) | 各 1 | 已有设备优先，没有的待询价 |
| 头模 | 标准成人头模，鼻梁和耳部支点位置可测 | 1 | 可 3D 打印 |
| 测力传感器 | 小量程薄膜压力传感器或称重传感器，分别放在鼻托与两耳支点下 | 3–4 | 量程按 0–200 g 力选 |
| 配重样架 | 3D 打印或改装镜框，前框与镜腿耳后段可加减配重块（每块 2–5 g） | 2–3 | 模拟 85 g、95 g、110 g 三档 |
| 电子秤 | 0.1 g 精度 | 1 | |
| 表面温度计 / 热像仪 | — | 1 | 可选，配合第 4 组发热观察 |

### 6.3 测试环境与前置条件

- 头模固定，眼镜佩戴位置用标记点统一。
- 主观测试至少 5 人，覆盖不同头型和是否戴近视眼镜；每人测试前说明可随时停止。

### 6.4 测试步骤

1. **称重**：每副对标眼镜与配重样架称重，记录前框、左右镜腿分段重量（可拆或用重心法估算）。
2. **头模受力**：在头模上测鼻托受力与左右耳支点受力，每副重复 5 次取平均。
3. **配重分布对照**：同一样架分别做“前重”（配重放前框）和“后重”（配重放耳后段）两种分布，在 85 g、95 g、110 g 三档下测鼻托受力。
4. **动态**：低头 30°、抬头、快走 2 分钟，观察是否下滑，测下滑距离。
5. **主观佩戴**：每人依次连续佩戴对标眼镜与“后重”样架各 2 小时（可分天），每 30 分钟用 5 分制记录舒适度、鼻梁压感、耳后压感；结束后记录压痕。
6. **对照结论**：比较“后重 110 g 样架”与对标产品的鼻托受力和主观评分。

### 6.5 测量指标与方法

| 指标 | 方法 |
| --- | --- |
| 鼻托受力（g 力） | 头模传感器读数，5 次平均 |
| 前后重量比 | 分段称重或重心测量 |
| 左右重量差（g） | 两侧镜腿分别称重 |
| 下滑距离（mm） | 标记点前后位置差 |
| 主观评分 | 5 分制，每 30 分钟一次，取均值与最低值 |

### 6.6 通过标准

| 项目 | 标准 | 依据 |
| --- | --- | --- |
| 鼻托受力 | “后重”样架在目标重量下的鼻托受力 ≤ 对标产品实测值 | 方案第 7.3 节【设计目标，非已验证结论】 |
| 左右对称 | 两侧镜腿重量差 ≤ 3 g | 方案第 7.3 节 |
| 主观舒适 | 2 小时主观评分不低于对标产品；无明显鼻梁压痕、耳后疼痛 | 方案第 7.3 节 |
| 前后重量比 | 目标接近 1:1，最终值待首轮测量后确定 | 方案第 7.3 节 |
