# 独立蜂窝 AI 眼镜 · 方案梳理

> 版本：v0.1 ・ 日期：2026-11-03
> 定位：自研眼镜整体方向梳理（串流终端 + 通用投屏兼容 + 强休眠）
> 说明：本文为**方向与技术要求梳理**，不是已验证的实现结论。文中标注「待验证」的部分尚未经过实测。

---

## 0. 一句话概括

做一副**以网络和视频处理为核心、把重计算放在外部主机、通过串流获得强体验**的独立蜂窝 AI 眼镜；通过投屏/转化层尽量兼容更多软件；并具备优秀的低功耗休眠与快速唤醒能力。

---

## 1. 目标一：Quest 2 级设备的「AR 眼镜版」——串流 + 有线实现超强体验

### 1.1 核心思路
把 Quest 2 这类一体机「本地算力扛渲染」的模式，改成**眼镜端轻量 + 外部主机扛算力 + 串流回传**的模式。眼镜本身不追求本地强算力，而是追求：

- **视频处理能力好**：低延迟解码、高刷新率显示、良好的画质还原。
- **网络能力强**：有线（主通道，追求超低延迟）+ 5G/Wi-Fi（移动/无线场景）。
- **可独立 5G 上网**：不依赖手机即可联网。
- **可拓展性强**：外设、主机、算力来源可替换升级。
- **续航好**：因为本地不做重渲染，功耗可控。

### 1.2 两种连接形态
| 形态 | 主通道 | 体验目标 | 适用 |
|---|---|---|---|
| 有线串流 | USB-C / 专用线 | 最低延迟、最高画质，「超强体验」 | 坐定/固定场景、重度使用 |
| 无线串流 | Wi-Fi 6E / 5G | 可移动，延迟略高 | 移动、轻度使用 |

### 1.3 眼镜端关键能力要求
- **解码**：硬件视频解码（H.264/H.265/AV1 视能力而定），目标端到端延迟尽量低。
- **显示**：分辨率、刷新率、亮度、FOV 需与串流画质匹配。
- **网络**：5G 基带 + 高带宽有线 PHY；无线场景下的抗抖动缓冲策略。
- **电源**：轻负载为主，续航目标需结合整机功耗预算设定。

### 1.4 可行性边界与待验证
- **延迟预算**：有线串流能否稳定做到「超强体验」所需的端到端延迟，取决于编码/传输/解码/显示各环节，**待验证**（建议先用投屏延迟计时器类工具实测基线）。
- **5G 模组功耗**：独立 5G 会显著影响续航，需做功耗预算；与「续航好」存在张力，需权衡。
- **散热**：高带宽解码 + 5G 在眼镜形态下的散热是硬约束。
- **外部主机依赖**：本形态强体验依赖外部主机（PC/手机/云/车机），主机可用性是前提。

## 2. 目标二：通过特殊投屏算法实现对「所有软件」的兼容

### 2.1 现状与边界（重要）
- 「之前研究的特殊投屏算法」——**原始技术资料需要确认对应本仓库中的哪份方案**（本目录下有多份投屏/渲染/推流相关调研报告，但本文不替其认定具体算法内容，避免虚构）。
- 「兼容所有软件」目前是**设计目标，不是已验证结果**。严格意义的「所有软件」在工程上通常不可达（存在 DRM、反投屏、硬件独占、系统级限制等），实际应表述为「兼容尽可能广的软件范围」。

### 2.2 兼容路线的几种技术方向（通用，不含具体私有算法）
1. **系统级投屏/镜像**：捕获系统显示输出后编码推流（兼容面广，但受 DRM/安全层限制）。
2. **渲染层接管**：在渲染管线层捕获画面（类 CarPlay/Android Auto 的接收端渲染思路，本目录已有相关深读报告）。
3. **转化 App / 中间层**：把目标软件输出转成眼镜可消费的标准流（兼容靠适配层，覆盖面取决于适配工作量）。

### 2.3 待确认 / 待验证
- **具体投屏算法**：请指明对应资料，再据此细化（**待确认**）。
- **DRM / 受保护内容**：此类内容通常无法投屏，属兼容边界（**边界**）。
- **兼容率**：应以「覆盖的软件类别清单 + 实测通过率」衡量，而非「全部兼容」（**待验证**）。

## 3. 目标三：强大的睡眠能力

### 3.1 含义待确认
「强大的睡眠能力」有两种可能解读，**需你确认**：
- **解读 A（低功耗休眠 + 快速唤醒）**：待机极低功耗、长时间挂机、抬手/语音/触摸毫秒级唤醒，恢复到上次状态。
- **解读 B（其他功能）**：如睡眠监测、助眠、夜间场景等健康向功能。

### 3.2 若为解读 A 的技术要求
- 分级功耗域：显示、5G、主控分别可独立进入低功耗。
- 唤醒源：传感器（IMU 抬手）、语音、触摸、网络唤醒。
- 状态保持与快速恢复：休眠不丢上下文，唤醒后秒回。
- 续航目标：待机功耗需定量指标（**待定**）。

## 4. 整体技术要求汇总

| 维度 | 要求 | 状态 |
|---|---|---|
| 视频处理 | 低延迟硬解、高刷显示 | 需实测延迟基线 |
| 网络 | 有线主通道 + 5G 独立上网 + Wi-Fi | 需选型 |
| 算力 | 本地轻量，重算力外置串流 | 方向明确 |
| 兼容 | 投屏/转化层覆盖尽量广的软件 | 兼容率待验证 |
| 续航 | 轻负载为主，待机强休眠 | 功耗预算待定 |
| 扩展 | 主机/外设/算力可替换 | 方向明确 |
